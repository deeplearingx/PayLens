# PayLens 事件语义归并评测

本报告记录本机 `BAAI/bge-small-zh-v1.5` ONNX 模型在固定中文合成样例上的对照结果。它只用于决定这版演示是否打开语义自动合并，不代表真实支付生产数据的效果。

模型修订为 `7999e1d3359715c523056ef9478215996d62a620`，ONNX SHA-256 为 `de07885703c40d7aa8caca2997594906169ffae212e5a5409c6da5e6d48b0518`。Java 端使用 CLS 池化、L2 归一化；与 Transformers 参考向量的最大差异约为 `1.23e-7`，参考排序测试通过。

开发集和保留集各含 100 条人工编写的中文观察记录，分属 10 类查单现象；每份数据形成 450 个同类正样本对和 4,500 个异类负样本对。两套描述互不重叠，只有描述文本进入向量模型；`eventLabel` 只在评测程序里计算指标。全部记录具有相同的商户、业务、阶段、通道、异常类型和错误码，因此本评测测量文本归并，不测跨硬边界行为。跨商户、业务阶段、通道和错误码的阻断由归并领域测试单独覆盖。

规则基线按规范化后的完整描述相等分组。语义候选阈值在开发集按 0.80 至 0.98、步长 0.02 搜索，要求成对精确率至少 95% 且召回高于规则基线；同召回时选较高阈值。开发集选出 0.82：成对精确率 100%（16 个正确合并、0 个错误合并），成对召回 3.56%（16/450）。用完全链接分组后，开发集聚类精确率仍为 100%，但聚类召回只有 2.00%（9/450）。规则基线没有相同描述，聚类召回为 0%。

冻结阈值 0.82 后，保留集得到成对精确率 100%、成对召回 1.33%（6/450）；完全链接聚类精确率 100%、聚类召回 1.11%（5/450）。规则基线聚类召回为 0%。没有出现错误合并，但语义归并漏掉了绝大多数同类观察，因而这组结果不足以支持自动分组在工作流中默认启用。

**结论：** 形式化的开发门槛通过，但绝对召回很低。PayLens 保持 `PAYLENS_INCIDENT_SEMANTIC_AUTO_MERGE=false`；未设置有效校准记录时也会回退为 `RULE_ONLY`。演示可展示本机向量推理、确定性分组约束以及人工拆分/合并审计，不应宣称本模型已经能可靠地自动识别支付故障事件。提升召回需要改进可用特征、描述质量或模型策略，再使用新的保留集重新评测。

固定数据由 [`generate-incident-grouping-cases.py`](../../scripts/generate-incident-grouping-cases.py) 生成，开发集和保留集见本目录。评测实现为 [`IncidentGroupingEvaluationTest.java`](../../paylens-demo/src/test/java/cn/daxpay/open/paylens/analysis/IncidentGroupingEvaluationTest.java)，机器汇总见 [`evaluation-20260926.json`](grouping-evaluation/evaluation-20260926.json)。运行前需要按 [本地模型准备说明](README.md#异常事件工作台与本地向量模型) 准备模型文件。
