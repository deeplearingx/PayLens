# PayLens 验证计划与当前结果

## 验证目标

验证 PayLens 对支付主链路的隔离性、异常证据的可信度、分析任务的并发与资源边界，以及演示服务的鉴权。测试结论只覆盖明确执行过的项目；单元测试通过不代表 DaxPay 全仓或真实资金链路无缺陷。

## 测试分层

| 层级 | 覆盖内容 | 主要手段 | 验收条件 |
|---|---|---|---|
| 构建与兼容性 | DaxPay 依赖模块、PayLens 模块、启动包 | Maven reactor；当前分支要求 JDK 25 | 测试模块通过，启动应用可打包 |
| 单元测试 | 脱敏、上下文限额、检索、结构校验、模型 HTTP 契约、任务状态 | JUnit 5；模型服务由本机 HTTP 假服务代替 | 边界值和失败输入产生稳定状态，不影响支付代码 |
| 并发测试 | 相同诊断合并、不同上下文隔离、队列拒绝与恢复 | 多线程 JUnit；100 路相同请求 | 相同输入单次模型调用；拒绝任务能在容量恢复后重新受理 |
| 数据库集成 | PostgreSQL 唯一键、排队上限、任务恢复、事件拆分/合并、版本冲突与审计 | `scripts/test-paylens-postgres-integration.ps1` 创建无卷临时 PostgreSQL，并为测试类分别建库 | 多连接竞争后数据库状态唯一且可恢复 |
| 业务流程 | 正常支付、回调丢失、关单后迟到成功、重复回调、查单未知、人工处置 | 运行中的 DaxPay、模拟通道和管理端登录 | 每个场景重复执行结果一致，AI 不改变支付状态 |
| API 与安全 | 登录要求、角色/权限、商户归属、任务归属、报告转义 | MockMvc/集成测试及匿名 HTTP 探测 | 匿名与越权请求拒绝；仅授权范围可读写 |
| AI 质量 | ChatClient HTTP 契约、假模型输出校验、ONNX 向量一致性、规则/语义归并及仅证据 vs 证据加检索 | JUnit、固定互斥开发/保留集；真实调用最多 40 次 | 记录原始测试环境与结果，不使用模型自评替代人工标注 |

## 关键流程与边界用例

### 支付业务

| 用例 | 操作 | 预期结果 |
|---|---|---|
| 正常成功 | 建单并发送模拟成功回调 | 本地订单成功；回调有记录；不生成待处理异常单 |
| 回调丢失 | 模拟通道成功但不回调，再执行 DaxPay 查单或回放 | 查单/回放前为处理中，恢复后成功；重复回放不产生第二个业务结果 |
| 关单后迟到成功 | 通过 DaxPay 关单服务关单，再提交成功回调 | 订单仍保持终态；生成一条待处理异常记录；不自动确认资金成功 |
| 重复回调 | 同一成功回调重复 100 次 | 最终业务状态稳定；待处理异常记录不重复创建 |
| 查单超时/未知 | 通道查单返回超时或未知 | 不推断支付成功或失败；确认成功动作被拒绝，异常单仍待处理 |
| 人工确认成功 | 并发执行确认与同步；确认前重查 | 只有最新查单明确成功且备注有效时才允许确认；审计记录完整 |
| 人工忽略 | 空备注、超长备注、正常备注 | 空备注拒绝；长备注按上限处理；成功后保留操作者、时间和说明 |
| 回调/处置竞争 | 回调、查单、确认、忽略并发竞争 | 条件更新与事务处理后订单、异常单和审计记录不矛盾 |

### AI 分析与输入边界

| 用例 | 操作 | 预期结果 |
|---|---|---|
| 敏感数据 | 伪造邮箱、手机号、API Key、Bearer、密码进入证据摘要 | 发往模型的快照先脱敏；报告/页面以文本方式展示 |
| 证据上限 | 31 条证据、单条超过 2,000 字符、UTF-8 编码后超过 16 KiB | 最多取 30 条；单条截断；总快照按 UTF-8 字节上限拒绝且不建任务 |
| 结构错误 | 非法 JSON、缺必填字段、空摘要、列表超限 | 任务失败，不将原始模型文本显示为成功结果 |
| 证据引用错误 | 事实/原因缺证据、引用不存在的证据 ID | 结果拒绝；原因必须含核查建议 |
| 知识引用错误 | 引用本次 Top-3 以外 ID、检索无匹配 | 无效引用拒绝；无匹配时允许分析并明确没有使用知识库 |
| 上下文隔离 | 证据、商户、模型标识或知识版本变化 | 不复用旧诊断；同一快照并发提交只产生一个模型调用 |
| 模型故障 | 429、5xx、头部超时、响应体延迟、格式错误、超过 64 KiB | 使用稳定失败码；不会调用支付处置逻辑；按规则显式重试 |
| 队列压力 | 工作线程与队列满、持久化队列满、恢复后再次提交 | 返回明确过载；请求线程不执行模型；线程池过载任务能重新受理 |
| 进程恢复 | 进程重启时存在 RUNNING 和 QUEUED 任务 | RUNNING 标记为重启失败；QUEUED 按容量恢复调度 |

### 2026-09-26 真实事件分析 A/B 评测补充

使用模型 `qwen3.7-flash-2026-07-15` 和固定数据集 `paylens-incident-eval-v1` 完成 38 次请求，两种输入条件各 19 次，不重试失败请求。38 次均收到服务商响应；22 份符合完整结构及引用校验，15 份因 JSON 字段类型不符合契约而失败，1 份引用了输入以外的证据 ID。Codex 按评分点完成 38 份语义评阅，均分仅证据 1.63/2、证据＋检索 1.68/2，配对 4 胜、4 负、11 平；这是 AI 评阅，且响应内容可暴露检索条件，不替代独立人工评分。结构通过数和 AI 语义分数均不能证明诊断准确率提高。Retrieval Recall@3 为 17/17，但两个没有预设候选知识的案例也都检索到 `query-timeout`，因此该 Recall 不反映无候选场景的误检。

评测期间的 v1 提示词未明确要求 `possibleExplanations[].verification` 必须是字符串。根据失败样例，当前代码已将提示词升至 v2，并增加类型契约测试；**v2 尚未经过真实模型调用**。本次 38 次消耗已落盘，未再次调用服务商。提示词和知识检索的版本化原始结果、Token、延迟、响应校验及人工评分材料见[评测报告](incident-evaluation-report.md)与 [原始产物目录](evaluations/incident-analysis-ab-20260926/)。

本地语义归并的详细机器指标、样本范围和边界见[归并评测报告](grouping-evaluation-report.md)及[机器结果](grouping-evaluation/evaluation-20260926.json)。当前测得的低召回是重要负面结果，不能通过降低阈值或只展示开发集结果掩盖；需要改进文本特征或算法后，用新的保留集重新评测。

## 可重复执行的验证命令

```powershell
# PayLens 单元回归
rtk proxy mvn -B -pl paylens-analysis,paylens-demo -am test

# 独立 PostgreSQL 任务队列测试；使用当前 Docker context 的临时无卷容器，结束后自动清理
rtk pwsh -NoLogo -NoProfile -File scripts/test-paylens-postgres-integration.ps1

# 独立 PostgreSQL/Redis/Artemis 上执行 20 轮真实确认/忽略并发竞争并清理临时容器
rtk pwsh -NoLogo -NoProfile -File scripts/test-paylens-payment-concurrency.ps1 -Rounds 20

# 同步与回调各并发 20 轮，并在同一隔离运行中验证 Chromium 工作台
rtk pwsh -NoLogo -NoProfile -File scripts/test-paylens-payment-concurrency.ps1 -RaceMode SyncCallback -Rounds 20 -BrowserSmokeTest

# 重复通知 100 次，并核验数据库回调审计记录
rtk pwsh -NoLogo -NoProfile -File scripts/test-paylens-payment-concurrency.ps1 -RaceMode DuplicateCallback100 -Rounds 1

# 已运行的本机应用上执行登录端到端流程，支持五种场景
rtk pwsh -NoLogo -NoProfile -File scripts/test-paylens-e2e.ps1 -Scenario LATE_SUCCESS
```

## 仍然存在的验证边界

本轮测试覆盖了三类支付并发行为和指定权限账号，但不代表 DaxPay 全部支付路径、多实例部署或真实通道都已证明正确。当前没有做高并发容量测试、长时间稳定性测试、真实支付渠道回调测试，也没有覆盖所有角色组合。浏览器验收使用假模型和合成订单。单笔诊断评测的人工盲评分表仍为空；事件评测已由 Codex 完成条件映射暂时隐藏的 AI 评分，但输出文本含检索引用线索，评分不是严格盲评或独立人工评估，不能据此宣称检索提高了诊断准确率。

因此，证据支持的结论是：**本轮结束时分析模块 46 项测试通过；同日此前归并领域 15 项和演示模块 11 项通过；10 项 PostgreSQL 集成测试通过；此前记录的 20 轮确认/忽略竞争、20 轮同步/回调竞争、100 次重复通知及审计行校验、指定权限矩阵，以及登录后的完整事件工作台浏览器流程均通过。** 本次改动后没有重跑整个 Maven reactor。最近一次浏览器运行另执行一轮确认/忽略竞争，不取代此前 20 轮结果。语义自动归并因保留集召回率低而默认关闭；v1 事件分析完整校验通过 22/38，Codex 的条件映射暂时隐藏均分为仅证据 1.63/2、证据＋检索 1.68/2，但仍待独立人工评阅；当前 v2 提示词未经真实模型验证；全角色矩阵、真实资金链路和生产容量仍未验证。不据此宣称“无残留 bug”或生产可用。
