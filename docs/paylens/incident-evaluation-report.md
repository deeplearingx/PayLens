# 事件诊断真实模型 A/B 评测

评测日期：2026-09-26。评测比较相同事件证据下的两种输入：仅提供脱敏证据，以及提供证据并附带关键词检索得到的最多三段故障知识。19 个事件各运行一次两种条件，共 38 次请求；失败请求不重试。每次发出请求前先写入预算账本。本轮计划上限为 40 次，实际使用 38 次，未使用剩余两次额度。

本次真实评测固定使用数据集 `paylens-incident-eval-v1`、模型 `qwen3.7-flash-2026-07-15`、生产提示词 `paylens-incident-prompt-v1`、输出结构 `paylens-incident-output-v1`，知识库版本为 `80d811dd5284af28`。数据集 SHA-256 为 `2cd739edf87a4f1a206e6c6ca9b6cf0d4c3be13d963772fd97743917e1d35ed5`；模型配置和提示词内容摘要见[固定清单](evaluations/incident-analysis-ab-20260926/manifest.json)。评测使用合成脱敏事件，不包含评分答案或候选知识标签作为模型输入。

服务商对 38 次请求均返回了响应。22 份输出通过完整结构与引用校验；16 份被拒绝，其中 15 份 JSON 语法有效，但 `possibleExplanations[].verification` 被模型输出为数组，与接口要求的字符串不符；另有 1 份结构有效的输出引用了输入中不存在的证据 ID `statistics`。单独看证据引用校验，22 份有效、1 份无效、15 份未评估；知识引用校验则为 22 份有效、0 份无效、16 份未评估。汇总文件中的 `structureValidity.valid=22` 表示完整校验成功数，并非独立的 JSON 类型检查数。被拒绝的输出会将任务标记失败，不会将原始文本伪装成成功诊断。

检索 Recall@3 为 17/17。分母是数据集里预先标注了匹配知识 ID 的 17 个合成案例；另外两个案例没有候选知识标签，但检索仍都返回了 `query-timeout`，因此 Recall@3 不反映这类无候选样例上的误检。该指标只说明关键词检索命中了预标注知识片段，不说明模型解释正确，也不衡量根因诊断准确率。证据＋检索组多产生 2 份结构有效结果，但单个小型合成数据集上的结构通过数不能证明检索改善了答案质量。

本次 A/B 请求共记录 21,892 个提示 Token 和 162,323 个完成 Token。延迟从请求发出到完整响应处理完成计量；中位数和 P95 均使用 nearest-rank 算法（排序后取 `ceil(p × N)` 对应项，偶数样本的中位数因此取下中位数）。没有可核实的本次服务商价格费率，因此没有推算费用。逐请求状态、延迟和 Token 可在[账本](evaluations/incident-analysis-ab-20260926/ledger.json)和[汇总](evaluations/incident-analysis-ab-20260926/summary.json)核对，38 份请求/响应保存在同目录的 `raw/` 子目录。

## 后续修改与质量结论

评测失败暴露出提示词没有明确约束若干 JSON 字段的类型。当前代码已将事件提示词版本升至 `paylens-incident-prompt-v2`，明确每个字段的类型，并要求 `verification` 使用单个字符串；同时把合法 JSON 但字段类型错误归为 `INVALID_STRUCTURE`，而不是 `INVALID_JSON`。分析模块最新测试为 46/46 通过。不过，本报告的 38 次云端结果全部对应 v1，v2 尚未实测，因此不能声称这个提示词修改已经改善真实模型输出。

评分表已按每个事件随机映射为 X/Y 填入 38 个逐项分数、引用支持标签和理由。Codex 在评分和理由锁定后才查看 X/Y 与条件映射，锁定内容摘要为 `43a73384c0a57f099e6fddb7c3ecfe0b6b7df0a4c771bc7f2169c6c339ff8dc0`。不过，模型输出本身包含知识引用字段，评分者可能从内容推测是否用了检索，因此这属于“条件映射暂时隐藏的 AI 评阅”，不是严格盲评，也不是独立人工评分。评分定义为：2 分表示覆盖要点且没有重要无据结论或不安全建议；1 分表示部分覆盖或有重要遗漏/过度推断；0 分表示重大矛盾、无据结论或不安全处置建议。

| 条件 | AI 评阅数 | 分数合计 | 平均分（0–2） | 引用支持：支持 / 部分 / 不支持 |
|---|---:|---:|---:|---:|
| 仅事件证据 | 19 | 31/38 | 1.6316 | 15 / 4 / 0 |
| 证据＋检索知识 | 19 | 32/38 | 1.6842 | 13 / 4 / 2 |

`CitationSupport` 标为“支持”表示引用可追到对应证据/知识且没有实质性错引；“部分”表示来源只支持结论的一部分或输出有明显外推；“不支持”表示引用不存在或结论与输入相矛盾。

逐事件配对比较中，证据＋检索组 4 例得分较高、仅证据组 4 例较高、11 例相同；平均差为 +0.0526/2，配对差的中位数为 0。分数由 AI 评阅者按合成案例要点打分，样本小且评阅并非独立人工，差异很小，不能据此宣称检索提高诊断质量。语义分数涵盖全部 38 份模型文本（包括自动结构校验失败的输出），结构可用性另行统计；不能把语义分数当成可运行成功率。引用支持标签中，证据＋检索组有 2 份“不支持”：一份引用了不存在的证据 ID，另一份把未知状态表述为已知资金结果并建议更新本地订单。`blind-rubric.csv` 保留逐案评分要点；含具体分数的逐输出记录在 `blind-score-sheet.csv`。

逐输出分数、引用支持标签和理由见[评分表](evaluations/incident-analysis-ab-20260926/blind-score-sheet.csv)；[评分标准](evaluations/incident-analysis-ab-20260926/blind-rubric.csv)同时记录每个案例的 X/Y 配对均分；机器可读汇总见[AI 评阅摘要](evaluations/incident-analysis-ab-20260926/ai-assisted-review-summary.json)。若要做严格人工评分，应只向评分者提供 X/Y 表和评分标准，不提供账本或 `raw/`；完成评分后再解开条件映射。`blind-key.json` 被 `.gitignore` 排除，避免评分前意外提交公开。

本次结果仍表明 v1 输出契约需要改进：结构和引用完整校验通过率为 57.9%。AI 评阅分数不能替代独立人工质量评估。v2 需要在新的、未参与本轮 A/B 的样例和明确的新调用预算下验证；本次没有重放失败样例，也没有在完成 38 次请求后追加调用。
